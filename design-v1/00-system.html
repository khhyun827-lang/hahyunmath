디자인 시스템 v1

관리자 시안 A3 「학생 도시에」를 기준 언어로 삼는다. 다른 시안은 화면을 합치는 방식으로 가져오지 않는다. 화면마다 역할을 먼저 정의하고, 그 역할에 가장 맞는 UX만 골라 A3의 언어로 번역해 들인다. 버튼·카드·색·서체·간격·아이콘·인터랙션은 13개 화면 전부 예외 없이 이 문서 하나를 따른다.

상단 메뉴와 서브탭은 ds.js의 NAV·SUBNAV 한 곳에서 생성한다. 13개 화면이 각자 <nav>를 손으로 적으면 반드시 어긋나기 때문이다.

01화면의 역할

먼저 각 화면이 무엇을 하는 자리인지 한 문장으로 정한다. 그 다음에 UX를 고른다. 순서가 뒤바뀌면 기능이 많은 화면이 되고, 제품이 아니게 된다.

11 질의응답과 12 채팅은 일부러 형태를 다르게 했다. 같은 «소통»이어도 글의 성격이 다르면 형태가 달라야 한다. 수식이 들어가는 긴 질문은 세로로 쌓고, 짧은 말이 오가는 대화는 말풍선으로 둔다. 형태를 억지로 통일하는 것은 일관성이 아니라 게으름이다 — 통일해야 하는 것은 색·서체·간격·버튼이지 레이아웃이 아니다.

같은 곳으로 가는 문은 하나만 둔다. 신호에 전용 화면이 생겼으므로 명단의 「위험 신호」 저장된 뷰는 없앴다. 명단에 남은 «신호 열»은 학생을 훑을 때의 맥락 표시이지 진입점이 아니다. 문이 둘이면 어느 쪽이 최신인지 매번 헷갈린다.

01-B학생 마이페이지

학생 마이페이지 11개 화면 → 관리자와 같은 토큰을 쓴다. 색·서체·반경·상태색·메모 종이색이 전부 같다. 바꾼 것은 밀도뿐이다 — 관리자는 앉아서 마우스로 쓰고, 학생은 서서 엄지로 쓴다.

  • 모바일 우선 390×812. 데일리퀴즈 제출·오답숙제 입력·강의 시청·클리닉 신청은 전부 학생이 폰으로 하는 일이다. 관리자와 같은 1440×900으로 그리면 실제로 쓰이지 않는 것을 검토하게 된다.
  • 탭 11개 → 4개. 홈 / 학습 / 기록 / 소통. 기능은 하나도 빼지 않고 묶기만 했다. 하단 탭바에 들어가는 것은 4~5개가 한계이고, 11개를 가로로 밀게 하면 뒤쪽은 아무도 안 누른다.
  • 누르는 것은 최소 46px. 관리자 화면의 32px 버튼을 그대로 쓰지 않는다.
  • 상태색 5종은 그대로. 학생이 보는 출석 달력의 색과 관리자가 보는 출결 도트의 색이 같아야 «같은 것»을 말하고 있다는 게 전달된다.

02무엇을 버렸는가

일관성을 해치는 것은 아무리 좋아 보여도 넣지 않는다. 하나의 제품처럼 보이는 것이 개별 화면의 완성도보다 앞선다.

  • A4의 다크 테마 — 처리함만 검은 화면이면 같은 제품이 아니게 된다. 큐 구조와 2열 비교, 키보드 조작만 라이트로 번역해 가져왔다.
  • A1의 파랑 선택색 #1F6FEB — 선택을 뜻하는 색은 시스템에 하나만 있어야 한다. 딥 올리브로 통일했다.
  • A1의 IBM Plex Sans KR — 본문 서체는 Pretendard 하나. 표가 좁아 보이는 문제는 서체가 아니라 tabular-nums와 행 높이로 해결한다.
  • A5의 3열 칸반 보드 — 신호 화면은 두되 보드는 버렸다. 카드 27장이 세 열에 흩어지면 «놓치지 않는» 화면이 오히려 산만해진다. A3의 연대기와 같은 idiom으로 등급으로 묶은 한 줄기 목록을 썼다 — 읽는 눈이 위에서 아래로 한 번만 움직인다.
  • 이모지 아이콘 — 플랫폼마다 모양이 달라 제품이 흔들린다. 인라인 SVG 한 벌로 교체했다.

03색

표면은 웜 페이퍼다. 순백 배경을 쓰지 않는다. 강조·선택·주요 액션은 전부 로고 차콜 하나로 처리한다. 상태색은 의미가 있을 때만 쓴다 — 장식으로 쓰는 순간 신호가 죽는다.

모든 색은 자체 로고(2024, PAPERFIT)에서 나온다. 로고는 차콜 #3F3537 → 와인 #BA5054 그라데이션이다. 주조색으로 차콜을 쓰고 와인은 브랜드 순간에만 아껴 쓴다 — 와인을 UI 강조에 쓰면 위험색 #B03A2E와 색상이 가까워 고밀도 표에서 «선택된 행»과 «위험한 학생»이 구분되지 않는다. 취향이 아니라 사용성 문제다.

출결 5상태 — 실제 도메인 값. 이 다섯 개 밖의 상태는 없다.

04서체

Noto Serif KR은 「그 화면이 다루는 대상의 이름」에만 쓴다. 학생 상세에서는 학생 이름, 수업에서는 반 이름, 명단에서는 화면 이름. 그 외 어디에도 쓰지 않는다. 이 규칙이 흔들리면 시스템이 무너진다.

09지켜야 할 것

  • 새 화면을 만들 때 색·서체·반경·간격을 새로 정하지 않는다. 화면별 <style>에는 «배치»만 둔다.
  • 주요(올리브) 버튼은 화면당 하나.
  • 상태색은 의미가 있을 때만. 예쁘라고 칠하지 않는다.
  • serif는 그 화면이 다루는 대상의 이름에만.
  • 숫자는 전부 JetBrains Mono + tabular-nums. 표에서 자릿수가 흔들리면 안 된다.
  • 모든 HTML에 word-break:keep-all. 없으면 한글이 음절 단위로 갈라진다.
  • 목업을 만들면 반드시 브라우저로 렌더링을 확인한다.

표시된 학생 이름·수치는 전부 구조 확인용 예시 데이터이며 실제 데이터가 아니다. 학교명·과목명·출결 상태·오답 검토 단계는 실제 도메인 값을 사용했다.
