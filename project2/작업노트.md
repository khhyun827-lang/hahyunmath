## 0-A. ★ 판정 기준 — 이것이 이 프로젝트의 전부다

> ### 목적은 «압축»이 아니다.
> **압축본만 익히면 4권의 모든 문항을 풀 수 있어야 한다.**
> 뺀 문제 중에 «압축본에서 배운 것으로 못 푸는 것»이 하나라도 있으면 안 된다.

그래서 물음이 뒤집힌다.

| | ❌ 잘못된 기준 (2026-08-16 이전) | ✅ 올바른 기준 |
|---|---|---|
| 물음 | 이 둘이 «닮았는가» | **대표를 익힌 학생이 이것을 «풀어낼 수 있는가»** |
| 기본값 | 닮았으면 지운다 | **남긴다** — 지우려면 «완전히 담긴다»를 보여야 한다 |
| 근거 | 유형 태그 · 난이도 점수 | **발상 · 조건 해석** |
| 사유 쓰는 법 | 「A-046과 동일」 | **「대표의 무엇이 이것을 덮는가」를 문장으로** |

**발상이 다르거나 조건 해석이 다르면 남긴다.**

### ⚠ 난이도 점수를 판정에 쓰지 않는다
해설 길이·경우 나누기 횟수로 재는 대리 지표라 **서술형은 부풀고 화살표로 적은 것은 눌린다.**
삭제 판정에도, SCENE 배치에도, SCENE3 안의 차례에도 쓰지 않는다. DB에 싣기만 한다.

### ⚠ 지운 사유에는 «대표 문항 ID»를 반드시 적는다
「동일」이라고만 쓰면 나중에 검증이 안 된다. 그리고 **대표가 다른 회차에서 지워지면
학습 요소가 통째로 사라지므로**, 판정이 끝나면 체인을 기계로 전수 확인한다.
(도형의 이동에서 실제로 3건이 끊겨 있었다 — `D-016 → B-011 → 삭제됨`)

### SCENE 배치도 «발상의 층»으로
| | |
|---|---|
| **SCENE1** 기본유형 | 배운 규칙을 «한 번» 적용. **유형마다 최소 형태 하나** (SCENE1이 빈 유형이 있으면 안 된다) |
| **SCENE2** 발전유형 | 조건이 «한 겹» 얹힌다. 조건을 식으로 번역 · 역추적 · 두 도형을 함께. **도구는 SCENE1 것 그대로** |
| **SCENE3** 실전 | **관점**이 필요하다. ① 방향이 뒤집힌다 ② 다른 영역으로 넘어간다 ③ 스스로 세워야 한다 |

⚠ **SCENE3는 «어려운 것»이 아니라 «다른 눈이 필요한 것»을 모으는 곳이다.**
계산만 무거운 것은 SCENE2에 둔다.

### ⚠ 검사기도 같은 함정을 밟는다
- `<hp:script>` 만 세다가 «수식 0개» 라고 보고했다
- 정답 대조에서 «3건 불일치» 가 나왔는데 셋 다 검사기 문제였다 —
  미주 자르기가 뒤쪽 본문까지 삼킴 · 해설 안의 «표»(벤다이어그램 5개·연산표)를 안 셈 · 조건이 «수식»이라 못 봄
- 문항 수 `123` 을 코드에 박아 둬서, 문항을 빼자 거짓 경고가 났다 → 파일에서 읽는다
- 쪽 장식을 걸러내자 «그림이 모자라다»고 했다 → 판정 규칙을 `decor.mjs` 하나로 모아 빌더와 공유

**검사기가 «다르다»고 하면 파일부터 의심하지 말고 검사기를 먼저 볼 것.**

### ⚠ 셸로 정규식이 든 JS 를 고치지 말 것
bash/sed 가 백슬래시를 먹어 `\d` → `d`, `\s` → `s` 가 된다. 코드가 «조용히» 깨진다.
이것 때문에 네 번 망가뜨렸다. **Edit 도구를 쓰거나, 새 파일을 Write 로 만들어 import 할 것.**

### ⚠ 미주를 채우는 순서
본문 앵커가 `<hp:t>문제</hp:t>` 라서, 해설에 「문제」라는 글이 있으면 미주 안쪽을 먼저 잡는다.
**본문을 먼저 꽂고 미주를 나중에** 채운다. (이 순서를 되돌리지 말 것)
