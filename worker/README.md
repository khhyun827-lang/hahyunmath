# AI_SITE_TOKEN 걷어내기 — 배포 순서

`gemini-proxy.js`는 참조 구현이다. **배포돼 있는 워커 소스가 이 저장소에 없어서**
`index.html`이 부르는 계약에 맞춰 인증·할당량 부분만 새로 썼다.
생성/업로드/삭제 핸들러 셋은 기존 워커에서 그대로 옮겨 붙여야 한다.

## 왜 «회전»이 아니라 «교체»인가

`AI_SITE_TOKEN`은 정적 클라이언트에 실려 모든 방문자 브라우저로 내려간다.
저장소에서 지워도 배포된 파일에는 남아 있어야 앱이 돌고, 새 토큰으로 갈아도
새 값이 똑같이 공개된다. **처음부터 비밀이 될 수 없는 값이었다.**

실제 위험은 노출 자체가 아니라 그 뒤에 아무 방어가 없다는 점이다 —
일 20건 제한이 클라이언트에만 있다(`index.html:731, 758`).
토큰만 있으면 워커를 직접 루프로 호출해 Gemini 비용을 태울 수 있다.

## 이 변경이 사주는 것 / 사주지 않는 것

산다 — 영구 정적 비밀 제거(1시간 만료·회수 가능한 토큰) · **서버 쪽 uid별 할당량** · uid 단위 추적.

**사지 못한다 — 「강사만 접근」.** `index.html:5401`이 `signInAnonymously()`라
Firebase 신원이 «사이트를 연 사람»까지만 말해 준다. 학생/강사 구분은 Firestore 대조(앱 레벨)라
Firebase 토큰에 실리지 않는다. 강사만 통과시키려면 커스텀 클레임이 필요하고,
클레임을 심을 권한 있는 백엔드가 따로 있어야 한다. 지금 구조에는 없다 — 별건이다.

## 순서 — 한 번에 갈아엎으면 실서비스가 죽는다

클라이언트를 먼저 바꾸면 워커가 `Authorization`을 모르는 상태라
프리플라이트에서 막혀 **AI 생성과 이미지 업로드가 그 자리에서 죽는다.**
반드시 워커부터다.

### 1단계 — 워커 (둘 다 받게)
- `gemini-proxy.js`의 인증·할당량·CORS를 기존 워커에 이식
- 비밀 `LEGACY_SITE_TOKEN`에 **지금 쓰는 토큰 값**을 넣는다 → 옛 클라이언트가 계속 돈다
- KV 네임스페이스 `QUOTA` 바인딩 (없으면 할당량 검사를 건너뛴다 — 로그에 남는다)
- `ALLOW_ORIGIN`을 실제 배포 도메인으로. `*`로 두지 말 것
- 확인: 옛 index.html에서 AI 생성 1건과 이미지 업로드 1건이 그대로 되는지

### 2단계 — 클라이언트 (`index.html`)
`AI_SITE_TOKEN` 상수와 `X-Site-Token` 헤더 3곳(`806, 1937, 1947`)을 지우고
이미 있는 `getAuthToken()`으로 바꾼다. Firestore REST가 쓰는 그 함수 그대로다.

```js
headers: { 'Content-Type': 'application/json',
           'Authorization': 'Bearer ' + await getAuthToken() }
```

`/upload`는 FormData라 `Content-Type`을 직접 넣지 않는다 —
브라우저가 boundary까지 붙여야 하므로 `Authorization`만 넣는다.

확인: 배포 후 AI 생성·업로드·삭제 3종. 401이 나오면 워커가 아직 1단계가 아니다.

### 3단계 — 옛 경로 닫기
- Cloudflare에서 **`LEGACY_SITE_TOKEN` 비밀 삭제** → 사이트 토큰 경로가 저절로 닫힌다
- 이때 비로소 유출된 값이 죽는다. 그 전까지는 살아 있다
- `Access-Control-Allow-Headers`에서 `x-site-token` 제거
- 확인: 옛 토큰으로 curl 하면 401

## 남는 것

`index.html`의 클라이언트 할당량(`AI_DAILY_LIMIT`)은 **UI 표시용으로만** 남긴다.
진짜 한도는 워커가 쥔다. 두 값이 어긋나면 «남았다고 떠 있는데 429»가 되니
`AI_DAILY_LIMIT`을 고칠 때 워커 상수도 같이 고쳐야 한다.

KV는 원자적이지 않아 동시 요청이 겹치면 한도를 한두 건 넘길 수 있다.
정확히 막아야 하면 Durable Object로 올린다. 1인 운영 · 일 20건에서는 «대충 20건»으로 충분하고,
지금처럼 «아예 안 막힘»과는 차원이 다르다.

**커밋 이력의 옛 토큰은 지워지지 않는다.** `585a77a`까지 origin/main에 올라가 있다.
이력을 다시 쓰는 것(filter-repo)은 이미 공개된 값을 회수하지 못하므로 의미가 없다.
3단계에서 무효화하는 것이 유일한 해결이다.
