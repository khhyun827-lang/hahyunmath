# Cloudflare 워커 — Gemini 프록시 + 드라이브 업로드

```
gemini-proxy.js   워커 본체. 배포본 + Firebase ID 토큰 검증 · 서버 쪽 할당량
verify-test.mjs   토큰 검증 테스트 (node worker/verify-test.mjs worker/gemini-proxy.js)
```

`gemini-proxy.js`는 **2026-08-06 시점의 배포본에 인증만 얹은 것**이다.
드라이브 OAuth·업로드·삭제·Gemini 프롬프트는 **한 줄도 건드리지 않았다.**
손댄 곳은 파일 맨 위 셋뿐이다 — CORS · 인증 게이트 · 할당량.

## 왜 «토큰 회전»이 아닌가

`AI_SITE_TOKEN`은 정적 클라이언트에 실려 모든 방문자 브라우저로 내려간다.
저장소에서 지워도 배포본에는 남아야 앱이 돌고, 새 토큰으로 갈아도 새 값이 똑같이 공개된다.
**처음부터 비밀이 될 수 없는 값이었다.**

실제 위험은 노출 자체가 아니라 그 뒤에 아무 방어가 없다는 점이다 —
일 20건 제한이 클라이언트에만 있다(`index.html:843, 871`).
워커는 아무것도 세지 않으므로, 토큰만 있으면 직접 루프로 호출해 Gemini 비용을 태울 수 있다.

## 이 변경이 사주는 것 / 사주지 않는 것

**산다** — 영구 정적 비밀 제거(1시간 만료·회수 가능한 토큰으로 대체) ·
**서버 쪽 할당량 강제** · uid 단위 사용량 추적.

**사지 못한다 — 「강사만 접근」.** `index.html:6093`이 `signInAnonymously()`라
Firebase 신원이 «사이트를 연 사람»까지만 말해 준다. 학생/강사 구분은 Firestore 대조(앱 레벨)라
토큰에 실리지 않는다. 커스텀 클레임을 심으려면 권한 있는 백엔드가 따로 있어야 한다 — 별건이다.

그래서 **비용은 막지만 방해는 못 막는다.** AI 생성에 전체 상한 20건/일을 걸었으므로
누군가 20건을 태우면 그날 강사가 못 쓴다. 청구서가 터지는 것보다는 낫다는 판단이고,
이걸 없애려면 위의 «강사만 접근»이 먼저 풀려야 한다.

## 배포 순서 — 한 번에 갈아엎으면 실서비스가 죽는다

클라이언트를 먼저 바꾸면 워커가 `Authorization`을 모르는 상태라
프리플라이트에서 막혀 **AI 생성과 이미지 업로드가 그 자리에서 죽는다.** 반드시 워커부터다.

### 1단계 — 워커 배포 (옛 클라이언트와 새 클라이언트를 둘 다 받는다)
- `gemini-proxy.js` 배포
- **비밀 `SITE_TOKEN`은 그대로 둔다.** 지금 값 그대로 → 옛 클라이언트가 계속 돈다
- KV 네임스페이스를 만들고 `QUOTA`로 바인딩
  ```toml
  [[kv_namespaces]]
  binding = "QUOTA"
  id = "..."
  ```
  안 하면 할당량 검사를 **건너뛴다** (워커 로그에 경고가 남는다)
- `ALLOW_ORIGIN`을 실제 배포 도메인으로. 안 넣으면 지금처럼 `*`다
  ```toml
  [vars]
  ALLOW_ORIGIN = "https://<실제 도메인>"
  ```
- **확인**: 지금 배포된 index.html에서 AI 생성 1건 · 이미지 업로드 1건이 그대로 되는가

### 2단계 — 클라이언트 (`index.html`)
`AI_SITE_TOKEN` 상수(**706**)와 `X-Site-Token` 헤더 **4곳**을 지우고
이미 있는 `getAuthToken()`으로 바꾼다. Firestore REST가 쓰는 그 함수 그대로다.

| 줄 | 무엇 | 비고 |
|---|---|---|
| **918**  | Gemini 유사문항 생성 | JSON — `Content-Type` 유지 |
| **2065** | `/upload` (파일 선택 업로드) | FormData — `Content-Type` 넣지 않는다 |
| **2075** | `/delete` | JSON — `Content-Type` 유지 |
| **2092** | `/upload` (hwpx 안의 base64 이미지) | FormData — 위와 같다 |

> 줄 번호는 **2026-08-07 기준**이다. 예전 README는 «3곳»이라고 적어 두었는데
> `/upload`가 두 군데(파일 선택 · hwpx 임포트)라 실제로는 4곳이다.
> 그대로 따라가면 hwpx로 올린 이미지만 조용히 401이 난다. 고치기 전에 `X-Site-Token`을 검색해서 세어 볼 것.

```js
headers: { 'Content-Type': 'application/json',
           'Authorization': 'Bearer ' + await getAuthToken() }
```

`/upload`는 FormData라 **`Content-Type`을 직접 넣지 않는다** —
브라우저가 boundary까지 붙여야 하므로 `Authorization`만 넣는다.

**확인**: 배포 후 AI 생성 · 업로드 · 삭제 3종. 401이 나오면 워커가 아직 1단계가 아니다.

> ⚠ **`ALLOW_ORIGIN`을 걸면 로컬(`127.0.0.1:8777`)에서는 워커를 부를 수 없다.**
> CORS가 배포 도메인만 허용하므로 AI 생성·이미지 업로드는 **배포된 사이트에서** 확인해야 한다.
> 로컬에서 확인할 수 있는 것은 «무엇을 보내는지»까지다 (fetch를 가로채 헤더를 본다).

### 3단계 — 옛 경로 닫기
- Cloudflare에서 **비밀 `SITE_TOKEN` 삭제** → 사이트 토큰 경로가 저절로 닫힌다.
  코드를 또 고칠 필요 없다 (`authenticate()`가 `env.SITE_TOKEN` 존재 여부를 먼저 본다)
- `Access-Control-Allow-Headers`에서 `X-Site-Token` 제거
- **이때 비로소 유출된 값이 죽는다.** 그 전까지는 살아 있다
- 확인: 옛 토큰으로 curl → 401

## 남는 것

- **`AI_DAILY_LIMIT`은 두 곳에 있다** — `index.html:707`와 `gemini-proxy.js:30`.
  어긋나면 «남았다고 떠 있는데 429»가 된다. 고칠 때 같이 고쳐야 한다.
  클라이언트 쪽은 이제 UI 표시용이고 진짜 한도는 워커가 쥔다
- **KV는 원자적이지 않다.** 동시 요청이 겹치면 한도를 한두 건 넘길 수 있다.
  정확히 막아야 하면 Durable Object로 올린다. 1인 운영·일 20건에서는 «대충 20건»으로 충분하고,
  지금처럼 «아예 안 막힘»과는 차원이 다르다
- **커밋 이력의 옛 토큰은 지워지지 않는다.** `585a77a`까지 origin/main에 올라가 있다.
  이력을 다시 쓰는 것(filter-repo)은 이미 공개된 값을 회수하지 못하므로 의미가 없다.
  3단계의 무효화가 유일한 해결이다

## 정답 형태 규칙 (2026-08-07)

**학생 답안칸이 받는 것은 둘뿐이다** — 숫자 입력, 아니면 ①~⑤ 보기 버튼
(`index.html`의 `isMultipleChoice` / `answerInputHTML`).
분수·무리수·음수·문자식이 정답이면 학생은 풀고도 **제출할 방법이 없다.**

그래서 `answerFormRule`로 두 갈래를 못박았다.

| | 조건 | `answer` |
|---|---|---|
| 1순위 주관식 | 정답이 1~999 자연수로 떨어지게 역산 | 숫자만 (`"12"`) |
| 2순위 객관식 | 그럴 수 없으면 (분수·무리수·음수·0·1000 이상·문자식…) | 보기 기호 (`"③"`) |

객관식이면 **문제 본문 맨 끝에 ①~⑤ 보기 다섯 개**를 넣게 했다. 그래야 `isMultipleChoice()`가
잡아내 학생에게 보기 버튼이 뜬다. 오답 보기는 «흔한 계산 실수»에서 나올 값으로 지시했다.

> 예전 규칙은 `"깔끔한 정수 또는 간단한 기약분수"`를 허용했는데,
> **기약분수가 바로 그 입력 불가 사례**였다.

**받는 쪽에도 안전망을 뒀다** (`index.html`) — 생성 모델은 규칙을 어길 수 있고,
어긴 문항이 조용히 학생에게 가면 아무도 못 푼다.
- `answerFormProblem()` — 검토 카드에 «학생이 답을 제출할 수 없는 형태입니다» 경고를 띄운다
- `advanceBankStatus('approved')` — 어긋난 문항은 **공개 자체를 막는다**
- `normalizeTwinAnswer()` — `formatRule`이 «수식은 $로 감싸라»라서 AI가 숫자에도 $를 두른다
  (실제로 `$155$`가 나왔다). 채점이 문자열 비교라 학생이 `155`를 내면 오답이 되므로 벗겨 둔다

`alg:none` · 모르는 `kid` · 형식 깨짐. **2026-08-06 기준 10/10 통과.**
