# 문항 코드를 교재에 심기 — 해마다 고쳐 올려도 창고가 안 어긋나게 (2026-09-09)

> 사용자 요청 (2026-09-09) — 「hwpx 문서에 코드를 붙이고 싶은데 다른 분들과 수정작업하면서
> 코드가 다른 문제에 복사될 가능성이 있어. 어떻게 코드 붙이는 게 좋을지 기획해줘.」
>
> 그 앞 요청 (2026-09-08) — 「교재를 공유하는 사람들이 있는데, 코드는 내 개인의 것이라
> 교재에 심어두되 다른 사람들 눈에는 안 보이게 숨기고 싶다.」
>
> 그리고 하루 끝에 **진짜 물음**이 나왔다 (0절) — 「**내년 버전**을 수정해서 다시 올려도
> 중복이 안 생기고, 수정된 것은 비교되고, **추가된 것만** 받아들이게 짜 줘.」
>
> 🔵 **셋은 다른 문제다.** 「숨기기」·「복사본 알아보기」·「해마다 다시 받기」는 서로를 안 풀어 준다.
> **아래는 세 번째 것이 뼈대다** (0절~0-D). 1~7절은 거기까지 온 길이고, 숨기기는 8절에 남겨 뒀다.

## 0. ✅ 정했다 — **창고 본문과 대조한다. 지문은 안 박는다** (2026-09-09)

> 사용자가 물었다 — 「새로운 한글파일을 입력했을 때 기존 우리 창고에 있는 코드와 비교해서
> 같은 문항인지 비교하면 되는 거 아니야? 일부만 달라졌으면 수정할 건지, 다 다른 문항이면
> 새로 코드를 붙일 건지. 코드를 잃어버리지만 않으면 해시가 필요할지 궁금해졌어.」
>
> 그리고 무엇을 하고 싶은지 말했다 (2026-09-09) — 「hwpx 파일이 코드가 달린 채로 **내년 버전**
> 만들 때 수정한 이후로 다시 업로드되어도 **기존 문제랑 중복해서 올려지지 않고**,
> **수정된 문제 비교 가능**하고, **추가된 문제만 창고에 받아들일 수 있도록**
> 코드 심는 법을 체계적으로 짜고 싶어.」

🔴 **맞는 말이었다. 재 보니 지문은 «창고 본문의 두 번째 벌»이다.**

| 왜 | |
|---|---|
| 창고에 이미 있다 | `items` 가 코드마다 **본문을 통째로** 들고 있다(564제) |
| 대조 비용이 0이다 | `items-push.mjs` 는 **어차피 창고를 통째로 읽고 시작한다**(그림을 지켜야 하니까) — 대조는 이미 읽은 것을 한 번 더 보는 일이다 |
| 🔴 규칙을 어겼다 | 지문은 그 본문의 해시다 — **«같은 값을 두 벌로 두지 말 것»**, 이 노트가 제일 여러 번 물린 그 규칙이다 |
| 창고 본문이 **더 강하다** | 지문은 「같나 다르나」만 답한다. 본문이 있으면 **뭐가 어떻게 달라졌는지 보여 줄 수 있다** — 사용자가 말한 「수정된 문제 비교 가능」이 그것이다 |

🔵 **두 벌이라서 생겼던 짐이 통째로 사라진다:**
· 「읽을 때마다 다시 박는다」(파일을 매번 다시 내야 하는 짐) → 없다. 창고는 늘 최신이다
· 「낡은 지문이 거짓말한다」 → 없다 · 「사람이 손대면 망가진다」 → 없다 · 미주가 지저분해지는 것 → 없다

🔵 **갈아타는 값이 0이다** (2026-09-09 실측) — 배포한 hwpx 다섯 파일에 **코드 564개 · 지문 0개**다.
  1단계는 사본에만 돌려 봤고 원본에 안 박았다. **되돌릴 것이 없다.**

⚠ **딱 하나 잃는다 — 파일 하나만 보고는 판정을 못 한다.** 창고가 있어야 한다.
  다만 이 일을 돌리는 사람은 사용자뿐이고 늘 창고가 있으니 실제로는 안 아프다.
⚠ **한 가지 반론** — 창고가 틀어지면(09-06 「원본 24개가 덮였다」) 대조 기준 자체가 오염된다.
  🔵 **그래도 답은 «모든 파일에 사본을 뿌리기»가 아니다** — 창고에 쓰는 문을 막는 것(아래 0-C)과
  백업(`backup.mjs`)이다. 그리고 **장부(`codes/K2-E.json`)가 세 번째 증인으로 이미 있다**(0-B ④).

## 0-A. 🔴 정말 풀어야 할 것 — **`item-code.mjs` 는 «처음 한 번»만 되는 도구다**

사용자가 말한 「내년 버전」이 바로 여기서 막힌다. 지금 코드를 매기는 자리는 이렇게 생겼다:

```js
const rows = items.map((it, i) => { const seq = FROM + i;   // ← 문서에 놓인 «차례»로 매긴다
```

| 지금 다시 돌리면 | |
|---|---|
| 그냥 돌린다 | 🔴 **멈춘다** — 「장부에 01단원이 이미 있다」 |
| `--replace` 를 준다 | 🔴 **더 나쁘다** — 그 단원을 통째로 지우고 **문서 차례대로 다시 매긴다.** 앞에 문항 하나만 끼워 넣어도 **뒤가 전부 한 칸씩 밀려**, 이미 파일에 심긴 코드·창고·학생 오답기록과 통째로 어긋난다 |

🔵 **`item-code.mjs` 머리말이 이미 그렇게 경고하고 있었다** — 「일련번호를 «교재에 실린 순서»로
  다시 뽑지 않는다. 문항 하나를 빼면 뒤가 전부 밀린다.」 **경고만 있고 그럴 길이 없었던 것이다.**

> ### ▶ 그래서 이 일의 뼈대는 하나다
> **이미 코드가 있는 문항은 코드가 진실이고, 코드 없는 문항에만 번호를 준다.**
> 「문서 차례」는 판단에서 통째로 빠진다 — 순서는 해마다 바뀌는 것이고, 코드는 안 바뀌는 것이다.

## 0-B. 판정표 — **파일 하나 × 창고** (지문 자리에 창고 본문이 들어갔다)

문항 하나마다 아래 중 **정확히 하나**다. 위에서부터 본다.

| # | 파일의 코드 | 창고에 그 코드 | 본문 | 판정 | 하는 일 |
|---|---|---|---|---|---|
| ① | 있다 · **파일 안에 2번+** | — | — | 🔴 **복사됐다** | **기계가 안 정한다.** 나란히 보여 주고 사람이 고른다 |
| ② | 있다 | 있다 | **같다** | 🔵 **그대로** | **아무것도 안 한다 — 안 올린다** |
| ③ | 있다 | 있다 | 다르다 | **고쳤다** | 뭐가 달라졌는지 보여 주고, **승인해야** 갱신한다 |
| ④ | 있다 | **없다** | — | 🔴 **모르는 코드** | 멈춘다. 장부에 있나 본다(장부에도 없으면 남의 코드거나 오타다) |
| ⑤ | **없다** | — | 창고 어딘가와 **똑같다** | 🔵 **코드를 잃었다** | 그 코드를 **돌려준다**(파일에 도로 심는다). **새 코드를 주지 않는다** |
| ⑥ | **없다** | — | 창고 어디와도 다르다 | **새 문항** | 장부 맨 뒤 +1 로 새 코드를 준다 |
| ⑦ | 코드는 다른데 **본문이 같다** | | | **겹친 문항** | 알린다 (`K2-03-E-0311` = `K2-03-E-0314`) |
| ⑧ | 창고에 있는데 **파일에 없다** | | | **빠졌다** | 🔵 **절대 안 지운다.** 세어서 보고만 한다 |

### 이 표가 사용자의 세 요구에 어떻게 답하나

| 사용자가 말한 것 | 어느 줄이 푸나 |
|---|---|
| 「기존 문제랑 **중복해서 올려지지 않고**」 | ②가 **쓰기 자체를 안 한다** · ⑤가 «코드 잃은 것»이 새 문항으로 들어오는 것을 막는다 |
| 「**수정된 문제 비교 가능**하고」 | ③ — 창고에 옛 본문이 있으니 **나란히 놓을 수 있다** |
| 「**추가된 문제만** 창고에 받아들일 수 있도록」 | ⑥만 통과시키는 `--only-new` |

### ④·⑤·⑥ 을 가르는 실측값 (564제 · 2026-09-09)

| 무엇 | 잰 값 |
|---|---|
| 본문 → 코드 되찾기가 **한 벌로** 되는가 (⑤) | **562 / 564제** |
| 못 되찾는 것 | **1무리 2제** — `K2-03-E-0311` = `K2-03-E-0314` (본문이 진짜 똑같다) |
| 장부 ↔ 본문 어긋남 | **0** (장부 564 · 본문 564 · 양쪽에 없는 것 0) |
| 본문 길이 | 최소 54 · 중간 188 · 최대 961자 · **40자 미만 0제** — 우연히 겹칠 만큼 짧은 것이 없다 |
| 다음에 줄 일련번호 | **0565** (01…0076 · 02…0185 · 03…0322 · 04…0430 · 05…0564) |

⚠ **일련번호는 (과목·책) 통으로 이어진다** — 단원마다 따로 세지 않는다.
  단원별로 세면 두 단원이 각자 `0001` 을 주장하고, 그러면 학생이 단원을 잘못 골라도
  «있는 코드»가 되어 **조용히 다른 문항이 나온다** (`item-code.mjs` 장부 규칙).

## 1. 무엇이 진짜 문제인가

지금 `tools/item-code-stamp.mjs` 가 **미주 맨 앞**에 보이는 글자로 코드를 넣는다.

```xml
<hp:t>[K2-03-E-0311]</hp:t>   <!-- 미주 번호 뒤, 「[정답]」 앞 -->
```

선생님들이 **문제 틀을 복사**하면 코드가 딸려간다. 그러면 한 코드가 두 문항을 가리킨다.

🔵 **이건 어디에 심느냐와 무관하다.** 미주든 개체 설명문이든 책갈피든, 복사하면 같이 복사된다.
  숨긴 자리는 오히려 더 나쁘다 — **아무도 안 보니 조용히 따라간다.**
  보이는 자리는 복사한 사람이 코드를 보고 지울 수라도 있다.

> 🔴 **그러니 이건 «어디에 숨길까»가 아니라 «복사본을 어떻게 알아볼까» 문제다.**

## 2. 낸 답 — 코드 옆에 «지문»을 같이 심는다

> 🔴 **접었다 (2026-09-09) — 0절을 볼 것.** 지문 자리에 **창고 본문**이 들어갔다.
> 아래는 «왜 지문 하나로는 못 가르는가»의 기록이다 — **판정 갈래 자체는 0-B 표로 그대로 옮겨졌다.**

```
[K2-03-E-0311|a3f91c7e]
 └ 코드            └ 그때 그 본문의 해시 앞 8자리
```

코드는 «이름», 지문은 «그때 그 몸». 둘이 어긋나면 무언가 일어난 것이다.

### 🔴 그런데 지문 하나로는 못 가른다 — 여기가 09-08 안에서 한 걸음 나간 자리다

지문이 안 맞는 까닭이 **둘**인데, 지문만 보면 똑같이 「불일치」로 보인다.

| 무엇이 일어났나 | 지문 | 맞는 대응 |
|---|---|---|
| 선생님이 **원본의 오타를 고쳤다** | 불일치 | 🔵 정상 작업이다. 본문을 갱신한다 |
| 선생님이 **복사해서 새 문제를 만들었다** | 불일치 | 🔴 복사본이다. 새 코드를 줘야 한다 |

**지문만 보면 오타 고침에도 「복사본입니다」가 뜬다.** 교재를 고치는 것이 원래 하는 일이므로
헛경보가 쏟아지고, 그러면 그 경보는 곧 무시된다.

### 🔵 그래서 **둘**을 같이 본다 — 「그 코드가 몇 번 나오나」 + 「지문이 맞나」

| 그 코드가 파일에 | 지문 | 판정 | 하는 일 |
|---|---|---|---|
| 0번 | — | 새 문항 | 코드를 새로 준다 |
| 1번 | 맞음 | 그대로다 | 잇는다 |
| 1번 | 틀림 | **원본을 고쳤다** (복사 아님) | 🔵 **조용히 갱신한다. 경보가 아니다** |
| 2번+ | — | **복사됐다** | 🔴 **기계가 정하지 않는다. 둘을 나란히 보여 주고 사람이 고른다** |

🔵 **「코드가 몇 번」이 복사를 잡고, 「지문」이 그중 누가 원본인지 «귀띔»한다.** 하나씩으로는 둘 다 못 한다.
⚠ 세는 자리는 **파일 하나 안**과 **창고 전체** 둘 다여야 한다. 다른 파일로 복사해 갈 수도 있다.

### 🔴 2번+ 일 때 기계가 정하면 안 되는 까닭 (2026-09-09에 찾았다)

처음엔 「지문이 맞는 쪽이 원본」으로 자동 판정하려 했다. **거꾸로 짚는 자리가 있다** —
**원본을 고치고 복사본은 안 고친 경우**, 지문은 손 안 댄 «복사본»을 원본이라고 가리킨다.

🔵 **그래서 2번+ 이면 순서만 매겨 둘을 나란히 보여 주고 사람이 고른다.**
  564제에 코드 중복이 **0건**이라 이 창은 거의 안 뜬다 — 자동화해서 아낄 것이 없는 자리다.

### ⚠ 지문은 «읽을 때마다 다시 박는다»

원본을 고치면 파일에 박힌 지문이 낡는다. 그대로 두면 다음에도, 그다음에도 「틀림」이 뜬다.
**창고에 이을 때마다 지문을 다시 박아 새 파일을 낸다.** 그러면 파일의 지문이 늘
«지난번에 확인한 몸»이고, **그 뒤의 고침만** 잡는다.
🔵 `item-code-stamp.mjs` 가 이미 «원본을 안 건드리고 새 파일로 낸다» — 그 결과가 다음 판의 원본이 된다.

## 2-B. 「한 글자만 고쳐도 지문이 통째로 달라지는데 그건 어떡하나」

> 사용자가 물었다 (2026-09-09) — 「해시 8자리는 띄어쓰기 하나만 수정해도 완전히 달라지지?」

**띄어쓰기는 안 달라진다** — 정규화를 먼저 걸기 때문이다(3절). 564제에 띄어쓰기를 넣어 봐도
지문이 바뀐 것은 **0제**다. 하지만 «진짜 고침»은 한 글자만 바꿔도 값이 통째로 뒤집힌다.
**해시는 「비슷함」을 모른다.** 이건 고칠 수 없는 성질이다.

🔵 **그런데 알 필요가 없다.** 「지문이 달라졌다」는 그 자체로 아무 경보도 아니기 때문이다 —
  경보는 **코드가 둘일 때만** 난다. 한 글자를 고치든 문장을 통째로 갈든 똑같이 「1번·틀림」이고,
  똑같이 **그냥 갱신**이다. 그러니 «얼마나 달라졌는가»를 잴 일이 없다.

### 🔴 닮음으로 「고친 것 / 딴 것」을 가르려다 접었다 — 안 갈린다 (실측)

`tools/similar-items.mjs` 의 닮음(뼈대+IDF)으로 갈릴까 재 봤다. 564제 · 단원 안에서:

| | 닮음 |
|---|---|

**겹친다. 임계값을 둘 자리가 없다.** 같은 단원 문항들은 발문이 판박이라 서로 다른 문제가

🔵 `similar-items.mjs` 머리말이 이미 그렇게 적고 있었다 — 「이 둘이 서로 변형인가는 글자로 못 가른다. 사람이 봐야 안다.」

⚠ **곁가지로 흠 하나를 찾았다** — `similar-items.mjs:62` 의 수식 명령 정규식
  `/\[a-zA-Z]+/g` 는 **백슬래시가 하나 빠져** 아무것도 안 문다(`\\[a-zA-Z]+` 여야 한다).

  🔴 노트 함정 목록의 「node 정규식에 백슬래시가 빠져 있었다」가 **두 번째로 나온 자리**다.

⚠ 파서 쪽은 「미주에 없으면 그 문항의 개체 설명문에서 찾는다」를 더하면 된다.
  미주를 먼저 보고 없을 때만 설명문을 보므로 **이미 심어 둔 564제는 그대로 읽힌다.**
