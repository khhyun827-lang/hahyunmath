# 문항 코드를 교재에 심기 — 복사본을 알아보는 법 (기획 · 2026-09-09)

> 사용자 요청 (2026-09-09) — 「hwpx 문서에 코드를 붙이고 싶은데 다른 분들과 수정작업하면서
> 코드가 다른 문제에 복사될 가능성이 있어. 어떻게 코드 붙이는 게 좋을지 기획해줘.」
>
> 그 앞 요청 (2026-09-08) — 「교재를 공유하는 사람들이 있는데, 코드는 내 개인의 것이라
> 교재에 심어두되 다른 사람들 눈에는 안 보이게 숨기고 싶다.」
>
> 🔵 **둘은 다른 문제다.** 「숨기기」와 「복사본 알아보기」는 서로를 안 풀어 준다 —
> 그래서 아래에서 **갈라 놓았다.** 복사본 쪽은 지금 지을 수 있고, 숨기기는 사용자 손이 한 번 필요하다.

---

## 1. 무엇이 진짜 문제인가

지금 `tools/item-code-stamp.mjs` 가 **미주 맨 앞**에 보이는 글자로 코드를 넣는다.

```xml
<hp:t>[K2-03-E-0311]</hp:t>   <!-- 미주 번호 뒤, 「[정답]」 앞 -->
```

선생님들이 **문제 틀을 복사**하면 코드가 딸려간다. 그러면 한 코드가 두 문항을 가리킨다.

🔵 **이건 어디에 심느냐와 무관하다.** 미주든 개체 설명문이든 책갈피든, 복사하면 같이 복사된다.
  숨긴 자리는 오히려 더 나쁘다 — **아무도 안 보니 조용히 따라간다.**
  보이는 자리는 복사한 사람이 코드를 보고 지울 수라도 있다.

> 🔴 **그러니 이건 «어디에 숨길까»가 아니라 «복사본을 어떻게 알아볼까» 문제다.**

---

## 2. 낸 답 — 코드 옆에 «지문»을 같이 심는다

```
[K2-03-E-0311|a3f91c7e]
 └ 코드            └ 그때 그 본문의 해시 앞 8자리
```

코드는 «이름», 지문은 «그때 그 몸». 둘이 어긋나면 무언가 일어난 것이다.

### 🔴 그런데 지문 하나로는 못 가른다 — 여기가 09-08 안에서 한 걸음 나간 자리다

지문이 안 맞는 까닭이 **둘**인데, 지문만 보면 똑같이 「불일치」로 보인다.

| 무엇이 일어났나 | 지문 | 맞는 대응 |
|---|---|---|
| 선생님이 **원본의 오타를 고쳤다** | 불일치 | 🔵 정상 작업이다. 본문을 갱신한다 |
| 선생님이 **복사해서 새 문제를 만들었다** | 불일치 | 🔴 복사본이다. 새 코드를 줘야 한다 |

**지문만 보면 오타 고침에도 「복사본입니다」가 뜬다.** 교재를 고치는 것이 원래 하는 일이므로
헛경보가 쏟아지고, 그러면 그 경보는 곧 무시된다.

### 🔵 그래서 **둘**을 같이 본다 — 「그 코드가 몇 번 나오나」 + 「지문이 맞나」

| 그 코드가 파일에 | 지문 | 판정 | 하는 일 |
|---|---|---|---|
| 0번 | — | 새 문항 | 코드를 새로 준다 |
| 1번 | 맞음 | 그대로다 | 잇는다 |
| 1번 | 틀림 | **원본을 고쳤다** (복사 아님) | 본문·지문을 갱신한다 |
| 2번+ | 하나만 맞음 | 맞는 쪽이 원본, 나머지가 **복사본** | 복사본에만 새 코드 |
| 2번+ | 전부 틀림 | 둘 다 고쳤다 — 어느 쪽이 원본인지 모른다 | 🔴 **멈추고 사람에게 둘을 보여 준다** |
| 2번+ | 전부 맞음 | 진짜 똑같은 문항이 둘 | 하나를 지우거나 새 코드 |

🔵 **「코드가 몇 번」이 복사를 잡고, 「지문」이 그중 누가 원본인지 가린다.** 하나씩으로는 둘 다 못 한다.
⚠ 세는 자리는 **파일 하나 안**과 **창고 전체** 둘 다여야 한다. 다른 파일로 복사해 갈 수도 있다.

`교재 코드파일/K2-E-0{1..5}-bodies.json` 5개 단원 564제로 쟀다.

| 무엇 | 잰 값 |
|---|---|
| 코드 중복 | **0건** — 🔵 지금 바닥이 깨끗하다. 심으려면 지금이 좋다 |
| 지문 충돌 (앞 8자리) | **1건** · 🔴 잣대의 흠이 아니다 — **본문이 진짜 똑같다** (아래) |
| 앞 8 / 12 / 64자리 | **결과가 같다** → **8자리로 충분하다** |
| 본문 길이 | 최소 54자 · 중간 188자 · 최대 961자. **40자 미만 0제** |

### 잣대 — 「보통」을 쓴다 (공백만 접는다)

```
모든 공백류(줄바꿈·탭·NBSP 포함)를 한 칸으로 모으고, 앞뒤를 턴다. 그 외에는 손대지 않는다.
```

| 본문을 이렇게 건드리면 | 지문이 |
|---|---|
| 줄바꿈 하나 더 · 가운데 공백 두 칸 · 앞뒤 공백 | **안 바뀐다** 🔵 |
| 숫자 하나 바꿈 · 글자 하나 지움 | **바뀐다** 🔵 |

⚠ 더 느슨한 잣대(공백을 아예 없애고 ①②③ 기호까지 지우는 것)도 재 봤는데 **결과가 같았다.**
  같은 값이면 **덜 손대는 쪽**을 쓴다 — 손댄 만큼 나중에 설명할 것이 는다.

### 🔴 곁가지로 찾은 것 — 교재에 **완전히 같은 문항이 둘** 있다

```
K2-03-E-0311  =  K2-03-E-0314     (03.원의방정식 · 글자 하나 안 다르다)
「좌표평면 위에 점 A(0,2), B(-2,-2), C(10,-8)이 있다. 삼각형 ABC와 원 x²+y²=r²의
 교점이 3개일 때, 양수 r의 값의 곱은?」
```

🔵 **걱정하시던 복사가 이미 일어난 자리다.** 지문 체계가 없었기에 아무도 모르고 지나갔다.
▶ **어느 쪽을 지울지는 사용자가 정해야 한다.** (둘 다 두고 싶으면 그대로 둬도 된다 — 위 표의 맨 아랫줄)

## 4. 숨길 것인가 — **별개 결정이고, 지금 안 정해도 된다**

🔵 **지문은 코드가 어디에 있든 똑같이 돈다.** 그래서 이 결정은 1단계를 막지 않는다.

| 길 | 🔵 | 🔴 |
|---|---|---|
| **미주에 보이게** (지금 그대로) | 이미 564제로 «한글이 지킨다»가 증명됐다 · 복사한 사람이 보고 지운다 = **스스로 고쳐진다** | 코드가 남에게 보인다 |
| **개체 설명문에 숨기기** | 안 보인다 · 문항마다 걸 자리가 있다(`자산 12@4x.png` 가 75/76문항에 정확히 하나) | 🔴 **한글이 저장 뒤에도 지키는지 아직 안 쟀다.** 사용자 손이 필요한 시험이다 |
| **공유용 사본을 따로 내기** | 가장 확실 — 주는 파일에 코드가 아예 없다 | 파일이 둘이 된다. 남이 고친 것을 도로 합칠 때 코드가 없어 못 잇는다 |
| **코드를 아예 안 붙이고 지문으로만 잇기** | 복사 중복이 원천적으로 없다 | 🔴 **「고친 원본」과 「새 문항」을 못 가린다** — 2절 표의 3번째 줄이 통째로 불가능해진다. 그래서 코드는 필요하다 |

▶ **권하는 것 — 1단계는 «보이는 자리»로 먼저 낸다.** 까닭 셋:
1. 한글 보존 시험(사용자 손)을 기다리지 않고 오늘 나간다
2. 이미 심은 564제를 손댈 것이 없다
3. **지문 체계가 서 있으면 나중에 숨겨도 안전하다** — 숨김이 위험했던 까닭이 「조용히 따라간다」였는데, 지문이 그 조용함을 없앤다

## 5. 지을 것 — 3단계

### 1단계 — 지문을 붙인다 (사용자 손 필요 없음 · 오늘 할 수 있다)

| 어디 | 무엇 |
|---|---|
| `tools/fingerprint.mjs` **(새)** | 정규화 + 해시. 🔴 **잣대는 여기 한 곳뿐이다** — 웹도 도구도 여기를 부른다 |
| `hwpx.js:538` `HWP_CODE_RE` | `[코드]` 와 `[코드\|지문]` 을 **둘 다** 받게 넓힌다 |
| `hwpx.js:574` `hwpEndnoteParts` | 지문을 떼어 따로 돌려준다. 🔵 **본문 글자에는 안 섞인다** |
| `tools/item-code-stamp.mjs` | 심을 때 `\|지문` 을 같이 박는다 |
| `tools/code-audit.mjs` **(새)** | 파일 하나 던지면 2절 판정표대로 표를 낸다 — **받은 파일을 «심기 전에» 훑는 길** |
| `tools/code-audit-test.mjs` **(새)** | 복사본·고친 원본·같은 문항 둘을 **일부러 만들어** 무는지 본다 |

🔵 **뒤로 호환** — 지문 없는 `[K2-03-E-0311]` 도 그대로 읽는다. 지문 없음은 «틀림»이 아니라
  **«못 가림»**이다. 564제는 손댈 것이 없고, 다음에 심을 때 자연히 붙는다.
🔴 **`hwpx.js` 하나만 고치면 웹도 도구도 같이 고쳐진다** — 09-05에 파서를 한곳으로 모아 둔 값이다.
⚠ 검사는 **망가뜨려 무는지**로 짓는다 — 통과만 보면 「검사 통과를 봤다로 읽었다」를 또 밟는다.

### 2단계 — 받는 자리에 문을 세운다

판정표를 **읽어 들이는 모든 자리**가 따르게 한다 — 웹 업로드(`storeItems` 경로) · `tools/items-push.mjs`.

🔴 **09-06의 「웹으로 올렸더니 원본 24개가 덮였다」가 바로 이 자리다.** 복사본이 원본을 덮으면 안 된다.
🔴 **「2번+ · 전부 틀림」이면 멈춘다.** 조용히 하나를 고르지 않는다 — 어느 쪽이 원본인지 기계는 모른다.

### 3단계 — 숨길지 정한다 (🙋 사용자 손이 필요)

1. 나 — 01단원으로 **시험용 파일**을 만든다(원본은 안 건드린다). 몇 문항의 설명문에 `[코드|지문]` 을 심는다
2. 🙋 사용자 — **한글로 열었다가 그냥 저장**
3. 나 — 살아남았는지 잰다. **이것이 유일하게 확실한 검사다**
4. 살아남으면 → 설명문으로 옮긴다. **지문 체계는 1단계 것을 그대로 쓴다**

⚠ 파서 쪽은 「미주에 없으면 그 문항의 개체 설명문에서 찾는다」를 더하면 된다.
  미주를 먼저 보고 없을 때만 설명문을 보므로 **이미 심어 둔 564제는 그대로 읽힌다.**

## 8. 남은 결정 — 사용자에게

1. **1단계를 지금 지을까** (보이는 자리 + 지문). 사용자 손 없이 오늘 나간다
2. **`K2-03-E-0311` 과 `K2-03-E-0314`** — 완전히 같은 문항이 둘이다. 어느 쪽을 지울까 (둘 다 둬도 된다)
3. **개체 설명문의 사람 이름 5곳** — 09-08에 알렸고 아직 답이 없다. 지울까
4. **숨기기(3단계)를 갈까** — 가려면 한글로 열었다 저장하는 손이 한 번 필요하다
