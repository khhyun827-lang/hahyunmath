# 문항 코드를 교재에 심기 — 복사본을 알아보는 법 (기획 · 2026-09-09)

> 사용자 요청 (2026-09-09) — 「hwpx 문서에 코드를 붙이고 싶은데 다른 분들과 수정작업하면서
> 코드가 다른 문제에 복사될 가능성이 있어. 어떻게 코드 붙이는 게 좋을지 기획해줘.」
>
> 그 앞 요청 (2026-09-08) — 「교재를 공유하는 사람들이 있는데, 코드는 내 개인의 것이라
> 교재에 심어두되 다른 사람들 눈에는 안 보이게 숨기고 싶다.」
>
> 🔵 **둘은 다른 문제다.** 「숨기기」와 「복사본 알아보기」는 서로를 안 풀어 준다 —
> 그래서 아래에서 **갈라 놓았다.** 복사본 쪽은 지금 지을 수 있고, 숨기기는 사용자 손이 한 번 필요하다.

---

## 1. 무엇이 진짜 문제인가

지금 `tools/item-code-stamp.mjs` 가 **미주 맨 앞**에 보이는 글자로 코드를 넣는다.

```xml
<hp:t>[K2-03-E-0311]</hp:t>   <!-- 미주 번호 뒤, 「[정답]」 앞 -->
```

선생님들이 **문제 틀을 복사**하면 코드가 딸려간다. 그러면 한 코드가 두 문항을 가리킨다.

🔵 **이건 어디에 심느냐와 무관하다.** 미주든 개체 설명문이든 책갈피든, 복사하면 같이 복사된다.
  숨긴 자리는 오히려 더 나쁘다 — **아무도 안 보니 조용히 따라간다.**
  보이는 자리는 복사한 사람이 코드를 보고 지울 수라도 있다.

> 🔴 **그러니 이건 «어디에 숨길까»가 아니라 «복사본을 어떻게 알아볼까» 문제다.**

---

## 2. 낸 답 — 코드 옆에 «지문»을 같이 심는다

```
[K2-03-E-0311|a3f91c7e]
 └ 코드            └ 그때 그 본문의 해시 앞 8자리
```

코드는 «이름», 지문은 «그때 그 몸». 둘이 어긋나면 무언가 일어난 것이다.

### 🔴 그런데 지문 하나로는 못 가른다 — 여기가 09-08 안에서 한 걸음 나간 자리다

지문이 안 맞는 까닭이 **둘**인데, 지문만 보면 똑같이 「불일치」로 보인다.

| 무엇이 일어났나 | 지문 | 맞는 대응 |
|---|---|---|
| 선생님이 **원본의 오타를 고쳤다** | 불일치 | 🔵 정상 작업이다. 본문을 갱신한다 |
| 선생님이 **복사해서 새 문제를 만들었다** | 불일치 | 🔴 복사본이다. 새 코드를 줘야 한다 |

**지문만 보면 오타 고침에도 「복사본입니다」가 뜬다.** 교재를 고치는 것이 원래 하는 일이므로
헛경보가 쏟아지고, 그러면 그 경보는 곧 무시된다.

### 🔵 그래서 **둘**을 같이 본다 — 「그 코드가 몇 번 나오나」 + 「지문이 맞나」

| 그 코드가 파일에 | 지문 | 판정 | 하는 일 |
|---|---|---|---|
| 0번 | — | 새 문항 | 코드를 새로 준다 |
| 1번 | 맞음 | 그대로다 | 잇는다 |
| 1번 | 틀림 | **원본을 고쳤다** (복사 아님) | 🔵 **조용히 갱신한다. 경보가 아니다** |
| 2번+ | — | **복사됐다** | 🔴 **기계가 정하지 않는다. 둘을 나란히 보여 주고 사람이 고른다** |

🔵 **「코드가 몇 번」이 복사를 잡고, 「지문」이 그중 누가 원본인지 «귀띔»한다.** 하나씩으로는 둘 다 못 한다.
⚠ 세는 자리는 **파일 하나 안**과 **창고 전체** 둘 다여야 한다. 다른 파일로 복사해 갈 수도 있다.

### 🔴 2번+ 일 때 기계가 정하면 안 되는 까닭 (2026-09-09에 찾았다)

처음엔 「지문이 맞는 쪽이 원본」으로 자동 판정하려 했다. **거꾸로 짚는 자리가 있다** —
**원본을 고치고 복사본은 안 고친 경우**, 지문은 손 안 댄 «복사본»을 원본이라고 가리킨다.

🔵 **그래서 2번+ 이면 순서만 매겨 둘을 나란히 보여 주고 사람이 고른다.**
  564제에 코드 중복이 **0건**이라 이 창은 거의 안 뜬다 — 자동화해서 아낄 것이 없는 자리다.

### ⚠ 지문은 «읽을 때마다 다시 박는다»

원본을 고치면 파일에 박힌 지문이 낡는다. 그대로 두면 다음에도, 그다음에도 「틀림」이 뜬다.
**창고에 이을 때마다 지문을 다시 박아 새 파일을 낸다.** 그러면 파일의 지문이 늘
«지난번에 확인한 몸»이고, **그 뒤의 고침만** 잡는다.
🔵 `item-code-stamp.mjs` 가 이미 «원본을 안 건드리고 새 파일로 낸다» — 그 결과가 다음 판의 원본이 된다.

## 2-B. 「한 글자만 고쳐도 지문이 통째로 달라지는데 그건 어떡하나」

> 사용자가 물었다 (2026-09-09) — 「해시 8자리는 띄어쓰기 하나만 수정해도 완전히 달라지지?」

**띄어쓰기는 안 달라진다** — 정규화를 먼저 걸기 때문이다(3절). 564제에 띄어쓰기를 넣어 봐도
지문이 바뀐 것은 **0제**다. 하지만 «진짜 고침»은 한 글자만 바꿔도 값이 통째로 뒤집힌다.
**해시는 「비슷함」을 모른다.** 이건 고칠 수 없는 성질이다.

🔵 **그런데 알 필요가 없다.** 「지문이 달라졌다」는 그 자체로 아무 경보도 아니기 때문이다 —
  경보는 **코드가 둘일 때만** 난다. 한 글자를 고치든 문장을 통째로 갈든 똑같이 「1번·틀림」이고,
  똑같이 **그냥 갱신**이다. 그러니 «얼마나 달라졌는가»를 잴 일이 없다.

### 🔴 닮음으로 「고친 것 / 딴 것」을 가르려다 접었다 — 안 갈린다 (실측)

`tools/similar-items.mjs` 의 닮음(뼈대+IDF)으로 갈릴까 재 봤다. 564제 · 단원 안에서:

| | 닮음 |
|---|---|
| (가) 고친 원본이 **가장 낮게** 나온 값 | **0.135** (맺음말을 「값은?」 → 「값을 구하시오.」로) |
| (나) **딴 문항**끼리 가장 높은 값 | **1.000** (같은 단원 · 숫자만 다른 문제) |

**겹친다. 임계값을 둘 자리가 없다.** 같은 단원 문항들은 발문이 판박이라 서로 다른 문제가
1.000 까지 나오고, 반대로 맺음말 한 줄만 바꿔도 0.135 까지 떨어진다.
🔵 `similar-items.mjs` 머리말이 이미 그렇게 적고 있었다 — 「이 둘이 서로 변형인가는 글자로 못 가른다. 사람이 봐야 안다.」

⚠ **곁가지로 흠 하나를 찾았다** — `similar-items.mjs:62` 의 수식 명령 정규식
  `/\[a-zA-Z]+/g` 는 **백슬래시가 하나 빠져** 아무것도 안 문다(`\\[a-zA-Z]+` 여야 한다).
  564제에서 **수식 토큰 2,060개가 통째로 빠진 채** 닮음을 재고 있었다.
  🔴 노트 함정 목록의 「node 정규식에 백슬래시가 빠져 있었다」가 **두 번째로 나온 자리**다.
  (고쳐도 위 결론은 안 바뀐다 — 고친 식으로도 딴 문항 최고가 1.000 이다.)

## 4. 숨길 것인가 — **별개 결정이고, 지금 안 정해도 된다**

🔵 **지문은 코드가 어디에 있든 똑같이 돈다.** 그래서 이 결정은 1단계를 막지 않는다.

| 길 | 🔵 | 🔴 |
|---|---|---|
| **미주에 보이게** (지금 그대로) | 이미 564제로 «한글이 지킨다»가 증명됐다 · 복사한 사람이 보고 지운다 = **스스로 고쳐진다** | 코드가 남에게 보인다 |
| **개체 설명문에 숨기기** | 안 보인다 · 문항마다 걸 자리가 있다(`자산 12@4x.png` 가 75/76문항에 정확히 하나) | 🔴 **한글이 저장 뒤에도 지키는지 아직 안 쟀다.** 사용자 손이 필요한 시험이다 |
| **공유용 사본을 따로 내기** | 가장 확실 — 주는 파일에 코드가 아예 없다 | 파일이 둘이 된다. 남이 고친 것을 도로 합칠 때 코드가 없어 못 잇는다 |
| **코드를 아예 안 붙이고 지문으로만 잇기** | 복사 중복이 원천적으로 없다 | 🔴 **「고친 원본」과 「새 문항」을 못 가린다** — 2절 표의 3번째 줄이 통째로 불가능해진다. 그래서 코드는 필요하다 |

▶ **권하는 것 — 1단계는 «보이는 자리»로 먼저 낸다.** 까닭 셋:
1. 한글 보존 시험(사용자 손)을 기다리지 않고 오늘 나간다
2. 이미 심은 564제를 손댈 것이 없다
3. **지문 체계가 서 있으면 나중에 숨겨도 안전하다** — 숨김이 위험했던 까닭이 「조용히 따라간다」였는데, 지문이 그 조용함을 없앤다

## 5. 지을 것 — 3단계

### ✅ 1단계 — 지문을 붙인다 (**끝냈다 · 2026-09-09**)

| 어디 | 무엇 |
|---|---|
| `hwpx.js` `hwpItemFpText()` **(새)** | 🔴 **가르는 잣대는 여기 한 곳뿐이다** — 웹도 도구도 이걸 부른다 |
| `hwpx.js` `HWP_CODE_RE` · `HWP_FP_RE` | `[코드]` 와 `[코드\|지문]` 을 **둘 다** 문다 |
| `hwpx.js` `hwpEndnoteParts` → `problems[].itemFp` | 심긴 지문을 떼어 따로 돌려준다. 🔵 **본문 글자에는 안 섞인다** |
| `tools/fingerprint.mjs` **(새)** | 그 잣대 위에 해시를 얹는다. `지문()` · `지문맞나()` (맞음/틀림/**못가림**) |
| `tools/hwpx-zip.mjs` **(새)** | 풀고 묶는 일. `item-code-stamp.mjs` 안에만 있던 것을 빼냈다 |
| `tools/item-fp-stamp.mjs` **(새)** | 지문을 박는다. **그리고 다시 박는다** |
| `tools/item-code-stamp.mjs` | 코드를 심은 뒤 지문 박기를 이어서 부른다 (`--no-fp` 로 끈다) |
| `tools/code-audit.mjs` **(새)** | 파일 하나 던지면 2절 판정표대로 표를 낸다 — **받은 파일을 «심기 전에» 훑는 길** |
| `tools/code-audit-test.mjs` **(새)** | **일부러 망가뜨린 파일 다섯 벌**로 검사가 무는지 본다 — **22가지 전부 통과** |

🔵 **뒤로 호환** — 지문 없는 `[K2-03-E-0311]` 도 그대로 읽는다. 지문 없음은 «틀림»이 아니라
  **«못 가림»**이다. 564제는 손댈 것이 없고, 다음에 심을 때 자연히 붙는다.
🔴 **`hwpx.js` 하나만 고치면 웹도 도구도 같이 고쳐진다** — 09-05에 파서를 한곳으로 모아 둔 값이다.
  기존 검사 8벌(225가지)도 전부 그대로 통과한다.

**실제로 돌려 본 것 (01단원 76문항):**
```
지문 박기 전  →  못 가림 76 · 그대로  0
지문 박기 후  →  못 가림  0 · 그대로 76      (묶었다 풀어도 살아남는다)
```
✅ **03단원을 훑었더니 `K2-03-E-0311 = K2-03-E-0314` 를 스스로 찾아냈다** — bodies.json 이 아니라
  **hwpx 파일에서 곧장**. 「코드는 다른데 본문이 같다」는 갈래를 감사에 넣어 둔 값이다.

### 🔴 검사가 처음 돌 때 잡은 것 둘 — 둘 다 노트에 이미 있던 함정이다

1. **지문이 망가지면 코드까지 통째로 잃었다.** 지문 자리를 `[0-9a-f]{8}` 로만 받게 했더니
   한 글자만 틀려도 `HWP_CODE_RE` 가 통째로 안 물어 **코드가 정답 글자에 섞였다** —
   ①꼴에서 겪은 그 흠이 지문 때문에 되살아난 것이다. 사람이 손으로 고칠 수 있는 자리라 실제로 난다.
   🔵 **무는 것은 넓게(`[^\]\s]{0,32}`), 값을 보는 것은 좁게(`HWP_FP_RE`).** 꼴이 틀리면 «없음»으로 떨어진다.
2. **검사가 «목차»를 고치고 있었다.** 본문을 한 글자 고쳐 보는 대목에서 `section0.xml` 을 골랐는데
   거기는 표지·목차라 **미주가 0개**다. 지문이 하나도 안 바뀌어 검사가 헛돌았다 —
   노트의 「교재 맨 앞 목차·표지가 첫 미주보다 앞에 있다」가 여기서도 물었다.
   🔵 미주가 있는 섹션의, **첫 미주 «뒤»**에서 고른다.

### 2단계 — 받는 자리에 문을 세운다
