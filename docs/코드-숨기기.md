# 문항 코드를 «남의 눈에 안 보이게» 심기 — 조사와 미결 (2026-09-08)

> 사용자 요청 — 「교재를 공유하는 사람들이 있는데, 코드는 내 개인의 것이라 교재에 심어두되
> 다른 사람들 눈에는 안 보이게 숨기고 싶어.」
>
> 🔴 **아직 정하지 않았다.** 사용자가 「고민을 좀 더 해보겠다」고 했다(2026-09-08).
> 아래는 **실제로 재 본 값**이다 — 내일 다시 재지 말 것.

## 지금 어떻게 심고 있나

`tools/item-code-stamp.mjs` 가 **미주 맨 앞**에 «보이는 글자»로 넣는다:

```xml
<hp:t>[K2-E-01-0001]</hp:t>   <!-- 미주 번호 뒤, 「[정답]」 앞 -->
```

🔴 **미주는 [정답]이 있는 자리라 공유받은 사람이 반드시 읽는다.** 가장 눈에 띄는 자리다.

## 잰 값 (엔딩크레딧 01단원 `_코드.hwpx` · 76문항)

| 무엇 | 잰 값 |
|---|---|
| `charPr`(글자 모양) | **42개 · 「숨김」 속성 없음** — 한글에 글자를 안 보이게 하는 표준 수단이 없다 |
| 책갈피 `bookmark` | **0개** — 쓸 수는 있으나 «한글이 보존하는지»가 이 파일로는 증명 안 됨 |
| 누름틀 `fieldBegin/End` | **0개** · 🔴 애초에 숨김이 아니다(내용이나 회색 안내문이 보인다) |
| 메모 `memo` | **0개** |
| **개체 설명문 `shapeComment`** | **2,679개** — 한글이 실제로 쓰고 보존하는 «안 보이는 글자 자리» |
| 수식 `equation` | 2,531개 · 🔴 **수식 안은 못 쓴다** — 렌더링되어 그림처럼 그대로 보인다 |

### 설명문에 지금 들어 있는 것

```
2531개  「수식입니다.」            ← 자동 문구
  76개  「그림입니다. … 자산 12@4x.png …」
  23개  「묶음 개체입니다.」
   8개  「사각형입니다.」
   5개  🔴 「장은영」              ← 사람 이름
```

🔴 **설명문에 사람 이름이 5곳 들어 있다.** 안 보이는 자리라 사용자도 몰랐다.
  나눠 주는 교재에 그대로 딸려 가고 있다 — **사용자에게 알렸다. 확인이 필요하다.**
🔵 동시에 이것은 «설명문은 보이지 않지만 파일에 남는다»는 산 증거다.

### 🔵 문항마다 «하나씩» 있는 개체를 찾았다

`자산 12@4x.png` 가 **문항마다 정확히 하나** — 75문항에 1개, 1문항에 0개.
그래서 **문항 1 : 코드 1** 로 걸 자리가 된다(0개인 문항은 첫 수식으로 대신한다).

## 🔴 그런데 사용자가 «무너뜨리는 것»을 찾았다

> 「교재를 공동작업하는 선생님들은 분명 문제의 틀을 복사해서 사용할 거고,
> 그러면 그 문제에 딸려 있는 자산12@4x.png 그림도 복사되면서 **코드가 딸려가** 중복이 생길 것 같아.」

맞다. 그리고 **숨긴 것이라 더 나쁘다** — 미주에 보이면 복사한 사람이 코드를 보고 지운다.
설명문은 아무도 안 보니 **조용히 따라간다.**

> 🔵 **일반화** — 숨긴 것은 복사될 때 «조용히» 따라간다. 보이는 것이 오히려 스스로 고쳐진다.
> 어느 자리에 숨기든(책갈피·설명문·흰 글자) 똑같다.
> **그러니 이건 «어디에 숨길까»가 아니라 «복사본을 어떻게 알아볼까» 문제다.**

## ▶ 그래서 낸 안 — 코드 옆에 «지문»을 같이 심는다

```
[K2-05-E-0431|a3f91c7e]
 └ 코드            └ 그때 그 본문의 해시 앞 8자리
```

| 코드 | 지문 | 뜻 | 어떻게 |
|---|---|---|---|
| 있음 | 맞음 | 진짜 그 문항 | 그대로 창고에 잇는다 |
| 있음 | **틀림** | 🔴 복사본이다 | 멈추고 「복사본입니다」 — 새 코드를 줄지 묻는다 |
| 없음 | — | 새 문항 | 코드를 새로 준다 |

🔵 이러면 **숨겨도 중복이 조용히 못 지나간다.** 복사해서 «고친» 경우도 잡힌다 —
지문이 달라지니 「다른 문항」이 되고, 그게 맞는 동작이다.

✅ 할 수 있는 근거:
· 파서가 이미 본문 글자를 뽑는다(564제로 확인)
· 해시는 브라우저와 node 가 **같은 값**을 내는 것을 09-06에 실측했다
  (`crypto.subtle.digest` = `createHash`)
⚠ 지문은 **정규화한 본문**으로 떠야 한다 — 빈칸·줄바꿈이 조금 달라졌다고 「복사본」이라 하면
  헛경보가 쏟아진다. 그 잣대는 실제 564제로 재서 정할 것.

## 🔴 아직 안 재 본 것 — 이것부터 해야 한다

**한글이 개체 설명문을 «편집·저장한 뒤에도» 지키는가?**
자동 생성된 문구라, 한글이 저장할 때 **다시 만들어 덮을 수도 있다.**
이게 안 되면 위 이야기 전체가 무의미하다.

▶ **재는 법** (정한 순서):
1. 나 — 01단원으로 **시험용 파일**을 만든다(원본은 안 건드리고 새 파일). 몇 문항의 설명문에 `[코드|지문]` 을 심는다
2. 🙋 사용자 — **한글로 열었다가 그냥 저장**
3. 나 — 살아남았는지 잰다. **이것이 유일하게 확실한 검사다**
4. 살아남으면 → 심는 도구 + 파서 + 검사를 짓는다

## 파서 쪽 — 고칠 자리는 한 곳

`hwpx.js` 의 `hwpEndnoteParts()` 가 미주 글자 맨 앞에서 코드를 뗀다:
```js
const m = ans.match(HWP_CODE_RE);
```
여기에 **「미주에 없으면 그 문항의 개체 설명문에서 찾는다」** 를 더하면 된다.

🔵 좋은 점 셋:
· `hwpx.js` 하나만 고치면 **웹도 도구도 같이 고쳐진다**(09-05에 파서를 모아 둔 값이다)
· 설명문은 `<hp:shapeComment>` 라 **본문 글자를 뽑는 길에 안 섞인다**
· 미주를 먼저 보고 없을 때만 설명문을 보면 **이미 심어 둔 564제는 손댈 것이 없다**

⚠ 참고 — 파서에 이미 `.replace(/수식입니다\.?/g,'')` 가 있다. 설명문 문구가 본문에 새어
  들어온 적이 있어 걷어내던 자리인데, 그게 곧 «설명문이 파서가 닿는 자리»라는 증거다.
