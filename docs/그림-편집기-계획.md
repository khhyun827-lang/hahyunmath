# 그림 편집기 계획 — 장면을 SVG 로 그린 «뒤» 이름표를 옮긴다

작성: 2026-09-11 · **같은 날 0·1·2단계를 지었다.** 3단계(인도선·눈금 범위 제한)는 남아 있다.
지은 자리 — `figure.js`(mathRuns·pins·build·layoutLabels·pinAll·setLabelText·labelBoxes) ·
`index.html`(「그림 이름표 편집기」 절 · figureDraftHTML · acceptFigureDraft · variantFigureNoteHTML · render 끝) ·
검사 `tools/figure-pins-test.mjs` · 헤드리스 굴림 `tools/figure-edit-probe.html`.
사용자의 말 — 「문제 변형할 때 그림 변형하는 작업 svg 로 그림 생성하고, 그 이후에 수식이나
점 이름 같은 걸 에디터로 이동시켜 겹쳐진 걸 수정할 수 있는 구조를 만들고 싶은데」.

---

## 0. 한 줄 판단

**찬성이다. 그리고 지금 구조가 이미 그 절반을 해 놓았다.**

그림은 이미 «AI 가 그린 SVG» 가 아니라 **«장면(scene) 데이터 → `figure.js` 가 그린 SVG»** 다
(`docs/기록-2026-08-이식.md` 「그림을 코드로 그린다」). 그래서 편집기가 할 일은 **SVG 를 고치는 것이
아니라 장면에 «이름표 자리» 몇 줄을 더 적고 다시 그리는 것**이면 된다. 그러면 —

- **AI 한도를 안 쓴다.** 옮기고 다시 그리는 건 브라우저 안의 산수다.
- **검산(`checks`)이 그대로 산다.** 이름표는 검산의 대상이 아니다 — 곡선·점·눈금 «값»은 안 건드린다.
- **저장 불변식이 안 깨진다.** 「저장하는 SVG 는 `renderScene()` 이 낸 것뿐」이 그대로다.

🔴 **가장 큰 갈림길 하나 — «SVG 편집기»를 만들지 않는다.** 화면에 뜬 SVG DOM 을 마우스로 끌어
그 DOM 을 직렬화해 저장하는 길은 쉬워 보이지만 셋이 한꺼번에 무너진다 (2절 ①). 편집기는
**«자리 잡기» 편집기**다 — 만질 수 있는 것은 글자(이름표)의 자리뿐이다.

## 1. 무엇을 만들 것인가

### 1-1. 장면에 «핀(pins)» 이 생긴다

```js
scene.pins = {
  'curve:0':     { x: 412, y: 96,  anchor: 'start' },   // 곡선 이름표 (y=f(x))
  'point:1':     { x: 130, y: 288, anchor: 'middle' },  // 점 이름표 (P)
  'xtick:2':     { x: 244, y: 260, anchor: 'middle' },  // 눈금 숫자 (5)
  'axis:origin': { x: 190, y: 250, anchor: 'end' },     // O · x · y
  'label:0':     { ... }                                 // 자유 배치 라벨
}
```

- **좌표는 SVG viewBox 의 px** (560×430) 다. 데이터 좌표(x=5.6)가 아니다.
  이름표는 «곡선 위 어디»가 아니라 «종이 위 어디»에 놓는 것이고, 창(`autoWindow`)이 안 바뀌는 한
  px 가 제일 정직하다. ⚠ 그래서 **viewBox 크기는 약속이 된다** (2절 ⑧).
- **핀이 없는 이름표는 지금처럼 자동으로 앉는다.** 옛 장면(핀 없음)은 한 글자도 안 고치고 그대로 그려진다.
- 🔴 **핀은 숫자 셋과 anchor 열거값뿐이다.** 글자는 여기 없다 — 글자는 장면의 원래 자리
  (`curves[].label` 등)에서 오고 `esc()` 를 지난다. 핀에 문자열을 두는 순간 새 주입 구멍이 된다.

### 1-2. `figure.js` 가 달라지는 것 (작다)

| 어디 | 무엇 |
|---|---|
| `renderScene` | 글자마다 **`data-lbl="curve:0"`** 을 단다. 핀이 있으면 그 자리에, 없으면 자동 자리에 놓는다 |
| `renderScene` | `opt.edit` 이면 글자 뒤에 **투명한 잡기 상자**(`<rect>`)를 깐다 — 13px 글자는 손가락으로 못 잡는다. 저장본에는 안 넣는다 |
| `labelSpot` | 핀으로 고정된 이름표를 **잉크로 센다** — 안 그러면 자동 이름표가 핀 위에 앉는다 |
| `verifyScene` | **핀을 무시한다.** 검산 결과는 핀이 있으나 없으나 같아야 한다 (검사로 붙든다) |
| 새 함수 `labelBoxes(scene)` | 이름표마다 «어림 글자 상자»를 돌려준다 — 겹침 경고와 node 검사가 쓴다 |

### 1-3. 편집기 (index.html)

**어디에 사나 —** 「그림 필요」 작업대의 초안 상자(`figureDraftHTML`) 안, 검산 통과 «뒤»
「이 그림으로 하겠습니다」 «앞». 그리고 **이미 붙은 SVG 그림**에도 「이름표 옮기기」 단추 하나
(`pbvimg` 문서에 `scene` 이 있으니 다시 그릴 수 있다 — 한도 0).

**할 수 있는 것 (1판) —**
- 이름표를 **끌어서** 옮긴다 (마우스·펜·손가락 — Pointer Events 하나로).
- **화살표 키로 1px, Shift 면 5px** 민다 — 태블릿에서 끌기는 거칠다. 미세 조정은 키가 낫다.
- 이름표 하나 「원래 자리로」 · 전부 「되돌리기」.
- 겹치면 **붉게 표시** (편집하는 기기의 `getBBox()` 로 잰다 — 2절 ⑤의 한계가 있다).
- 다 되면 「이 그림으로 하겠습니다」 → **svg + scene(핀 포함)** 을 지금과 같은 문서에 저장.

**할 수 없는 것 (일부러) —**
- 곡선·점·눈금의 **값**은 못 옮긴다. 옮기는 순간 문제가 거짓이 된다 — 그건 장면 JSON 을 고치는 일이고
  검산을 다시 지나야 한다.
- ~~글자 **내용**은 1판에서 못 고친다~~ → **1판에 넣는다** (2026-09-11 · 사용자가 골랐다, 5절 1번).
  이름표를 두 번 누르면(길게 누르면) 작은 입력칸이 뜨고, 글자는 `esc()` 를 지나 장면의 원래 자리
  (`curves[].label` 등)에 쓰인다. **추가·삭제는 안 된다** — 있는 것의 글자만 바꾼다.
- 이름표를 **새로 못 만든다.** `labels[]`(자유 배치)에 넣는 건 2판.

### 1-4. 끌기의 실제 구조 — 이 코드베이스의 함정 하나

🔴 **`render()` 는 `#app` 을 통째로 `innerHTML` 로 다시 그린다.** 끌 때마다 `render()` 를 부르면
붙잡고 있던 SVG 요소가 사라져 끌기가 끊긴다. 그래서 —

```
pointerdown  → 어느 이름표인지(data-lbl) 기억. 첫 손길이면 «모든 이름표를 지금 자리에 핀»
pointermove  → render() 안 부른다. 그 <text> 의 x/y 만 직접 고친다 (살아 있는 DOM)
pointerup    → scene.pins 갱신 → renderScene 한 번 → render() 한 번
```

- «첫 손길에 전부 핀» — 하나만 핀하면 나머지 자동 이름표가 잉크가 달라졌다고 **딴 데로 옮겨 앉는다.**
  강사가 안 만진 것이 움직이면 그건 편집기가 아니다.
- 화면 좌표 → viewBox 좌표는 **`svg.getScreenCTM().inverse()`** 로 — `.pb-svg svg{width:100%}` 라
  화면에서는 0.7배쯤으로 줄어 있다. 비율을 손으로 곱하면 폭이 바뀔 때 어긋난다.
- svg 에 **`touch-action:none`** — 없으면 태블릿에서 끌 때 페이지가 같이 스크롤된다.
- 3px 안의 움직임은 «누른 것»이지 «끈 것»이 아니다 — 안 그러면 보려고 만졌는데 옮겨진다.

### 1-5. 수식 — 어디까지

지금 이름표는 `<text>` 에 이탤릭 세리프 **평문**이다. `y=f(x)`·`P`·`O` 는 이걸로 충분하다.
사용자가 「수식」이라 했으니 어디까지 갈지 정해 둔다 —

| | 되나 | 어떻게 |
|---|---|---|
| 아래첨자·위첨자 (`x_1`, `x^2`, `P_1`) | **2판에서 된다** | `_{}`·`^{}` 만 읽어 `<tspan baseline-shift>` 로. SVG 순정이라 저장·인쇄·태블릿 다 그대로 |
| 분수·근호·시그마 | **안 한다** | KaTeX 를 `foreignObject` 로 넣으면 html2canvas(리포트 PDF)·구형 태블릿에서 깨진다. 이런 이름표는 그림 밖 본문에 두는 게 맞다 |

## 2. 미리 보이는 문제들 — 그리고 어떻게 피할지

| # | 문제 | 왜 생기나 | 피하는 길 |
|---|---|---|---|
| ① | **SVG 를 직접 고치면 셋이 무너진다** | (a) 장면과 SVG 가 갈라져 «다시 그리기»가 편집을 지운다 (b) DOM 을 직렬화해 저장하면 «renderScene 의 산물만 저장」 불변식이 깨져 **주입 구멍**이 된다 (c) 다시 받기·창 바꾸기 뒤 편집이 통째로 사라진다 | **편집기는 장면(핀)만 고친다.** SVG 는 언제나 `renderScene(scene)` 의 결과 |
| ② | **안 만진 이름표가 딴 데로 간다** | 자동 자리(`labelSpot`)는 잉크를 피해 앉는데, 핀 하나가 잉크를 바꾼다 | 첫 손길에 **전부 핀** (1-4) |
| ③ | **끌다가 끊긴다** | `render()` 가 DOM 을 갈아 끼운다 | pointermove 동안 render 금지 · pointerup 에 한 번 (1-4) |
| ④ | **손가락으로 못 잡는다** | 학생 앱에서 13px, 강사 태블릿도 비슷하다 | 편집 모드에서만 투명 잡기 상자(글자 상자 + 8px). 저장본에는 안 넣는다 |
| ⑤ | 🔴 **강사 화면에선 안 겹치는데 학생 태블릿에선 겹친다** | SVG 는 글꼴을 **안 담는다** — 글자 «자리»만 적고 글꼴은 **보는 기기 것**을 쓴다. 지금 `Georgia, Times New Roman` 인데 **안드로이드엔 둘 다 없다** → 대체 세리프의 글자 폭이 달라, 강사 PC 에서 딱 맞게 놓은 이름표가 태블릿에서 옆 것과 닿을 수 있다. 자리는 같고 **글자 폭만** 다르다 | 🔵 **원인을 없앤다 — 기기 글꼴을 안 쓴다.** 앱이 이미 모두에게 Google Fonts 로 `Noto Serif KR` 을 내려 주고 있다(index.html 15줄). 그림 글자를 `'Noto Serif KR', Georgia, serif` 로 바꾸면 **강사도 학생도 같은 글꼴 파일**을 받아 폭이 같아진다. 0단계에서 한다. ⚠ 이탤릭이 없어 브라우저가 기울여 만든다(모든 기기가 같은 방식이라 폭은 같다). ⚠ 글꼴이 아직 안 내려온 첫 몇백 ms 는 대체 글꼴로 보인다 — `display=swap` 이라 그렇다. 잠깐이고, 이미 본문 전체가 그렇게 뜬다 |
| ⑥ | **멀리 옮기면 누구 이름표인지 모른다** | 곡선 둘일 때 `y=g(x)` 를 빈자리로 보내면 g 가 어느 곡선인지 사라진다 | 앵커에서 **N px 넘게 떨어지면 가는 인도선**(leader)을 자동으로 긋는다 — 원본 시험지도 화살표로 뺐다. 3판 |
| ⑦ | **눈금 숫자를 옮기면 값이 거짓이 된다** | 「5」가 x=5 자리에서 떨어지면 그건 5 가 아니다. `O` 도 마찬가지 | 눈금·원점은 **작은 범위(±20px)만** 밀린다. 그 밖은 인도선이 붙거나 거부 |
| ⑧ | **렌더러를 손보면 핀이 어긋난다** | 핀이 px 인데 언젠가 viewBox·여백·글자 크기를 바꾸면 전부 밀린다 | (a) **viewBox 560×430 은 약속** — 바꾸려면 핀 이관을 같이 짓는다 (b) 핀에 `size:[560,430]` 을 같이 적고 **다르면 핀을 버리고 자동으로** (c) 이미 붙은 그림은 **저장된 SVG 가 지킨다** — 다시 그리는 건 편집할 때뿐 |
| ⑨ | **잘못 끌었다** | 보려고 만졌는데 움직였다 · 엉뚱한 데로 갔다 | 3px 문턱 · 이름표마다 「원래 자리로」 · 전체 「되돌리기」 · 저장 전엔 아무것도 안 쓴다 |
| ⑩ | **다시 받기 뒤 옛 핀이 남는다** | 새 장면은 곡선 수·점 수가 다를 수 있다 | 「다시 받기」는 **핀을 버린다.** 핀은 «이 장면»의 것이다 |
| ⑪ | **이미 공개된 문항의 그림을 고치면** | 학생이 보는 그림이 바뀐다 | 이름표 자리만이라 **허용**한다. 다만 `pbvimg` 를 다시 쓰는 것이라 Firestore 쓰기 1건 · 캐시(`state.pbImageCache`) 갱신을 잊지 말 것 — 안 그러면 강사 화면은 옛 그림을 계속 보인다 |
| ⑫ | **검산이 «통과했다»가 편집 뒤에도 참인가** | 핀이 검산에 끼면 편집이 결과를 바꿀 수 있다 | `verifyScene` 은 핀을 안 본다 — **검사**: 핀을 아무렇게나 넣어도 결과가 같다 · 핀 밖의 키를 하나라도 바꾸면 검사가 문다 |
| ⑬ | **핀에 이상한 값** | 워커가 낸 장면이 아니라 강사 브라우저가 만든 값이지만, 저장은 저장이다 | `Number`·`isFinite`·viewBox 안으로 clamp · anchor 는 `start|middle|end` 만. 아니면 그 핀은 버린다 |
| ⑭ | **node 검사가 `getBBox` 를 못 쓴다** | 겹침을 진짜로 재는 건 브라우저뿐 | 순수 함수(`labelBoxes`·`applyPins`·`hitTest`)는 어림 상자로 node 에서 검사하고, DOM 을 만지는 껍데기는 얇게 둔다. **화면에서 한 번은 눈으로** (이 노트의 오랜 규칙) |
| ⑮ | **리포트 PDF 에 이 그림이 들어가는가** | html2canvas 는 SVG `<text>` 글꼴을 가끔 다르게 찍는다 | 지금 리포트에 변형 그림이 들어가는지부터 **확인**한다. 들어가면 배포본에서 PDF 한 장을 찍어 본다 |

✅ **0·1·2 는 2026-09-11에 끝났다.** 지으면서 계획과 달라진 것 —
· 핀은 `{ size:[560,430], at:{id:{x,y,anchor}} }` 꼴이다 — `size` 가 다르면 통째로 버린다(2절 ⑧-b).
· 글자 고치기는 두 번 누르기가 아니라 **누르면 아래 도구줄에 입력칸**이 뜬다 — render() 가 DOM 을
  갈아 끼우는 구조라 떠 있는 입력칸은 살아남지 못한다. 결과는 같다.
· 이탤릭·로만 규칙(1-5 를 넘어서)을 같이 넣었다 — 사용자가 시켰다. 예전엔 `<g font-style="italic">`
  하나로 「5」도 「=」도 기울어 있었다. 이제 `mathRuns()` 가 조각마다 정한다.
· 글꼴은 `Noto Serif`(라틴, 진짜 이탤릭) → `Noto Serif KR` 순이다. index.html 의 Google Fonts 요청에
  `Noto+Serif:ital` 을 더했다 — 모두가 같은 파일을 받는다.
· 점 이름표를 곡선 이름표보다 먼저 앉히고 **잉크로 센다** — 곡선 이름표가 점 이름을 피한다.
  (전에는 안 피했다. 저장된 그림은 다시 안 그리므로 승인된 그림은 안 바뀐다.)

0·1 이 한 덩이다 — 1 없이 0 은 아무것도 안 보이고, 0 없이 1 은 지을 수 없다.
**⑤(글꼴)는 0단계에서 원인을 없앤다** — 그림 글꼴을 앱이 이미 내려 주는 `Noto Serif KR` 로.
그러면 학생 태블릿이 따로 필요 없다 (배포본을 아무 기기에서 한 번 보면 된다).

## 3-½. 갈래 규칙도 같이 바꿨다 (2026-09-11 · 사용자 제안)

편집기가 서자 사용자가 물었다 — 「새로 그리는 게 어느 정도 정확도가 있고 에디터로 수정이 가능하면
C→B→A 순서로 가는 것에 대해 어떻게 생각해?」. **함수 그래프에 한해서는 맞다**고 답했고 그렇게 했다.

- `worker/gemini-proxy.js` `taskRule` 에 **①「좌표평면 위의 함수 그래프면 무조건 (B)」** 를 맨 앞에 세웠다.
  (A)는 그래프를 글로 옮기면서 원본보다 길고 어려운 문제를 만든다(08-11 확인) — 그래프를 «읽는» 문제는
  그래프를 «읽는» 문제로 남아야 쌍둥이다.
- **② 그 밖의 그림은 그대로 C→A→B.** 도형·지도·입체는 아직 사람이 그린다. 통째로 뒤집으면 「그림 필요」 큐가
  사람 몫으로 찬다. 가르는 기준은 «사람 일이 적은 순»이 아니라 **«기계가 그릴 수 있나»** 다.
- figureSpec 에 «식을 세울 수 있는 수»(절편·꼭짓점·교점·특정 값)를 적으라고 못박았다 — 그래야 `checks` 가 선다.
- ⚠ 솔직한 한계 둘 — 초안 정확도는 5건 안팎에서 «식으로 푸는 것은 다 맞았다» 정도로 **아직 잰 값이 아니다**
  (검산 + 사람 눈이 문을 지키니 위험은 낮다). 그리고 그래프 문항은 이제 **하루 한도 2건씩** 든다.
- 재는 도구 — `tools/figure-branches.mjs [날짜]`.

## 4. 안 하기로 미리 정해 두는 것

- **AI 에게 «겹치니 다시 놓아라»고 안 시킨다.** 한도를 쓰고, 검산을 다시 지나야 하고, 다른 데가 또 어긋난다.
  겹침은 사람이 3초에 푸는 일이다.
- **범용 도형 편집기를 안 만든다.** 선 긋기·색 칠하기·자유 곡선 — 그건 다른 물건이고, 그림을 «검산할 수
  있다»는 이 설계의 값어치를 버리는 길이다.
- **워커는 안 건드린다.** 장면 스키마에 `pins` 가 «생기지만» 워커는 그것을 내지 않는다 — 자리는 사람이 잡는다.

## 5. 열린 물음 — 2026-09-11에 닫혔다

1. 이름표 **글자 고치기** → **1판에 넣는다.** 까닭 — 지금은 장면(scene)을 고칠 칸이 **아예 없다**
   (`variantFigureSpec` 은 읽기 전용 `rv-spec`). 글자 하나가 틀리면 「다시 받기」로 **AI 한도 하나**를
   쓰거나 손으로 그려야 한다. 「문이 둘」 걱정은 헛것이었다 — 문이 하나도 없었다.
   범위는 «있는 글자 바꾸기»뿐 · 추가·삭제 없음 · `esc()` 를 지난다.
2. 학생 태블릿 → **필요 없다.** 사용자가 「내가 보는 그림과 학생이 보는 그림이 다를 수 있느냐」고
   물었고, 답은 «글꼴 폭만큼은 다를 수 있다»였다. 기기를 구해 재는 대신 **원인을 없앤다** (2절 ⑤).
3. 공개된 문항의 그림 → **고칠 수 있게 둔다** (⑪). 사용자가 그렇게 정했다.
